# Barreau Alger — خدمة التسبيقات والتأجيلات

## طريقة العمل المعتمدة
- لا توجد حسابات للمحامين؛ المحامي يرسل الطلب مباشرة من النموذج العام دون تسجيل دخول.
- لكل محكمة/هيئة حساب أدمن محلي مستقل، ويمكن الاحتفاظ بحساب مساعد منفصل عند الحاجة.
- الأدمن المحلي يرى طلبات هيئته فقط؛ الأدمن العام يدير الهيئات ويطلع على جميع الطلبات.
- الأدمن العام ينشئ حسابات المساعدين ويتابع كل الطلبات.
- تُعزل طلبات كل هيئة بواسطة PostgreSQL Row Level Security (RLS).
- لا تُخزّن ملفات القضايا في هذه الخدمة.

## الملفات
- `migrations/20261012000000_court_requests.sql`: الجداول والسياسات والهيئات الأولية.
- `functions/admin-create-assistant/index.ts`: دالة إنشاء حساب مساعد (للتوافق مع الإعداد السابق).
- `functions/admin-create-court-admin/index.ts`: دالة آمنة لإنشاء أدمن مستقل لكل هيئة، ولا تستجيب إلا للأدمن العام النشط.
- `functions/submit-court-request/index.ts`: استقبال طلبات المحامين والتحقق من الهيئة وحفظ الطلب. نقطة النهاية مضبوطة حاليًا على `verify_jwt=true` كإجراء احترازي؛ لن يعمل الإرسال العام دون جلسة حتى نضيف CAPTCHA والتحقق الخادمي ثم نعيد فتحها بأمان.
- `requests.html`: نموذج عام للمحامي ولوحة دخول المساعد والأدمن.
- يحتوي الطلب على رقم القضية، اسم الموكل وصفته (المتهم أو الضحية)، بيانات المحامي، نوع الطلب ونوع الجلسة وتاريخها.
- `../requests.html`: واجهة الدخول وتسجيل الطلبات وإدارة الحسابات.

## إعداد Supabase
1. استخدم مشروع Supabase مخصصًا لـ Barreau Alger. لم يتم اختيار أو تعديل أي مشروع موجود تلقائيًا لأن أسماء المشاريع الحالية لا تثبت أنها تخص هذا التطبيق.
2. راجع قائمة الهيئات في ملف الترحيل مع القائمة الرسمية الحالية قبل اعتمادها نهائيًا.
3. طبّق ملف SQL من Supabase SQL Editor أو بعد مراجعته محليًا عبر Supabase CLI.
4. أنشئ حساب الأدمن الأول يدويًا في Supabase Auth، ثم أضف صفًا مطابقًا له في `public.profiles` مع `role='admin'` و`court_id=NULL`. في إعدادات المستخدم (app_metadata) عيّن `role=admin` و`active=true`. لا تستخدم `user_metadata` للصلاحيات.
5. انشر Edge Functions `admin-create-court-admin` و`submit-court-request` بعد مراجعتهما، وتأكد من توفر أسرار `SUPABASE_URL` و`SUPABASE_SERVICE_ROLE_KEY` في بيئة الوظائف فقط. لا تضع مفتاح الخدمة في الواجهة.
6. أنشئ أول مستخدم للأدمن العام يدويًا في Supabase Auth ببريد تملكه المنظمة، ثم أضف صفًا له في `public.profiles` بدور `admin` و`court_id=NULL` و`active=true`. من إعدادات المستخدم في Auth، عيّن `app_metadata` إلى `{"role":"admin","active":true}`. يجب أن يتطابق البريد وUUID بين Auth و`profiles`.
7. فعّل Realtime لجدول `court_requests` إن لم يفعله ملف الترحيل تلقائيًا، واختبر وصول الطلب الجديد إلى لوحة المساعد. تظهر الطلبات داخل التطبيق؛ الإشعارات خارج التطبيق (البريد/الهاتف) غير مهيأة في هذه المرحلة.
8. نموذج الإرسال العام مقفول حاليًا بواسطة `verify_jwt=true`. قبل فتحه للجمهور، أضف CAPTCHA مثل Cloudflare Turnstile والتحقق الخادمي من الرمز، وحدودًا لمعدل الطلبات ومراقبة إساءة الاستخدام، ثم غيّر `verify_jwt` إلى `false` فقط بعد نجاح الاختبار. حقل honeypot وحده ليس حماية كافية للإطلاق العام.
9. في صفحة `requests.html` استبدل `YOUR_SUPABASE_URL` و`YOUR_SUPABASE_PUBLISHABLE_KEY` بالقيم العامة من إعدادات المشروع. المفتاح العام قابل للظهور في المتصفح؛ الأمان يعتمد على RLS. لا تضع مفتاح `service_role` أو secret key في الصفحة.
10. فعّل/اختبر حساب مساعد لكل هيئة تجريبية، وتحقق من أن المساعد لا يستطيع رؤية طلبات هيئة أخرى أو تعديلها، وأن الطلب العام يصل فقط إلى الهيئة المختارة.

## ملاحظات أمنية قبل الإطلاق
- كلمة المرور المؤقتة تُعرض للأدمن مرة واحدة بعد إنشاء الحساب. سلّمها للمساعد بطريقة آمنة، وفعّل آلية تغيير كلمة المرور قبل التشغيل الفعلي.
- تعطيل الحساب يجب أن يضبط `app_metadata.active=false` ويُلغي الجلسات القائمة؛ إخفاء الحساب في الواجهة وحده لا يكفي.
- لا تستخدم بيانات قضايا حقيقية أثناء الاختبار.
- اختبر سياسات RLS بحساب أدمن وحسابين لمساعدين تابعين لهيئتين مختلفتين.
- لا تنشر على Vercel قبل نجاح الاختبارات المحلية ومراجعة إعدادات Supabase.
- قائمة الهيئات المزروعة مستندة إلى ما يظهر في الموقع الرسمي لمجلس قضاء الجزائر، ويجب مراجعتها قبل اعتمادها لأن الموقع يذكر 7 محاكم في صفحة التعريف ويعرض كذلك ملحقة الحراش ومحكمة شراقة ومحكمة الجنايات في صفحة المحاكم.

## إنشاء أول حساب للأدمن العام (مرة واحدة)
1. من Supabase Dashboard افتح Authentication → Users وأنشئ مستخدمًا بالبريد الإلكتروني الذي تملكه وتريد تخصيصه للأدمن العام. لا تستخدم بريدًا افتراضيًا.
2. انسخ UUID الخاص بالمستخدم، ثم افتح SQL Editor ونفّذ الاستعلام التالي بعد استبدال `AUTH_USER_UUID` و`اسم الأدمن العام` بالقيم الصحيحة:

```sql
-- لا تنفذ هذا قبل إنشاء المستخدم في Authentication → Users.
update auth.users
set raw_app_meta_data = coalesce(raw_app_meta_data, '{}'::jsonb)
  || '{"role":"admin","active":true}'::jsonb
where id = 'AUTH_USER_UUID'::uuid;

insert into public.profiles (id, display_name, role, court_id, active)
select id, 'اسم الأدمن العام', 'admin', null, true
from auth.users
where id = 'AUTH_USER_UUID'::uuid
on conflict (id) do update
set display_name = excluded.display_name,
    role = 'admin',
    court_id = null,
    active = true;
```

3. سجّل الخروج ثم الدخول من جديد حتى يحصل الحساب على JWT claims المحدّثة. بعد ذلك افتح لوحة التسبيقات والتأجيلات؛ ستظهر لوحة إدارة الهيئات وإنشاء حساب أدمن لكل هيئة.
4. أنشئ لكل هيئة حسابًا ببريد فعلي تابع للمسؤول المعني. كلمة المرور المؤقتة تظهر مرة واحدة؛ سلّمها عبر قناة آمنة واطلب تغييرها بعد أول دخول.
5. لا تنشئ حسابات بهويات أو عناوين بريد مختلقة، ولا تشارك كلمة مرور الأدمن العام.

## ملاحظات إدارة الهيئات
- يمكن للأدمن العام إضافة هيئة، وتعديل اسمها ونوعها، وتفعيلها أو تعطيلها، ومحاولة حذفها نهائيًا.
- الحذف النهائي سيفشل بأمان عند وجود طلبات أو حسابات مرتبطة بسبب قيود المفاتيح الخارجية؛ في هذه الحالة عطّل الهيئة بدل حذف سجلها.
- لا تُنشأ حسابات بأسماء أو عناوين بريد مفترضة. يجب استخدام بريد صالح ومملوك للمسؤول، وتسليم كلمة المرور المؤقتة بطريقة آمنة.
